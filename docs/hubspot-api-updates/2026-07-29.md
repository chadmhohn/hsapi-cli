## Contracts

The current product guide documents:

- `GET /crm/objects/2026-03/contracts`
- `GET /crm/objects/2026-03/contracts/{contractId}`

HSAPI already provides these as `hsapi crm list contracts` and `hsapi crm get contracts <contractId>`. The current dedicated OpenAPI also publishes the read-only batch route, which is available as `hsapi crm batch-read contracts`.

Requirements are Revenue Hub Professional or higher and OAuth scope `crm.objects.contracts.read`. Contract search still uses the generic CRM search template and should be portal-validated before an automation depends on it because it is absent from the current Contracts guide and dedicated OpenAPI.

The current date-versioned guide does not publish contract writes. Legacy v3 write pages and an unannounced generated `2026-09` specification are not treated as authority for the forthcoming public beta. The new Contracts context page records the acceptance checklist: wait for an announced beta path, public scope/auth contract, lifecycle/body semantics, mutation gates, preview tests, and a disposable-portal live proof.

## Price Books beta

HubSpot moved the documentation navigation from `commerce/price-books` to `revenue/price-books`; API routes remain `/commerce/price-books/2026-09-beta/...`.

Typed reads:

- `hsapi price-books list`
- `hsapi price-books get <priceBookId>`
- `hsapi price-books items-list <priceBookId>`
- `hsapi price-books item-get <priceBookId> <priceBookItemId>`
- `hsapi price-books validate <priceBookId>`

The validation operation is a semantically read-only POST and is cataloged with `readOnlyPost: true`, so it is eligible for the read-only MCP executor when the tool call also supplies `readOnly: true`.

The beta requires Revenue Hub Professional. Current public operation pages use:

- `cpq.price_books.read` for reads and validation
- `cpq.price_books.write` for mutations

The family guide separately lists `crm.objects.products.read`, while generated OpenAPI uses an internal product-library alias on product-copy and item-update operations. Because the public operation pages list only `cpq.price_books.write`, the catalog records this discrepancy in notes rather than modeling the public product-read scope as jointly required without live proof.

Follow-up validation established that these are private-app access scopes, not selectable public-app OAuth scopes. The catalog therefore marks the family as admin audience; dual-auth profiles route through the local ServiceKey. The hosted brokers, public apps, and remote MCP deliberately exclude Price Books.

## Beta conflicts held behind catalog-only writes

- The narrative guide says book deletion uses `PATCH` with `archived=true`; generated endpoint reference/OpenAPI also publishes `DELETE`.
- The guide says item archive/restore shares the item `PATCH` path and that archived items purge after 90 days; generated endpoint reference/OpenAPI also publishes `DELETE`.
- Create-book required fields differ between the guide and generated schema.
- Batch-create full-success status differs between the guide and OpenAPI (`200` versus `201`); both describe `207` partial failures.

The shared PATCH paths are conservatively marked destructive. Both DELETE routes are destructive and experimental. Typed beta writes should wait for a beta-enabled disposable portal to resolve these contracts.
